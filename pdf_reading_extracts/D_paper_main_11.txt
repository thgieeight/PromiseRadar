Abstract
This paper studies whether a hair-style memory architecture can use structured placement
to retrieve the right item more effectively than a strong flat content-addressed baseline. Across
a long sequence of synthetic experiments, the main positive result is that multi-root assignment
and larger root shortlists substantially improve candidate coverage. The main negative result
is that this stronger candidate exposure still does not reliably translate into better end-to-
end retrieval than flat key matching, because the final within-pool selector remains too weak
and current spiral root maps are often too concentrated. The later experiments sharpen both
points. A PCA-aligned spiral map is the first spiral variant in these experiments that becomes
reasonably competitive in a favorable latent-manifold regime, and QDMN-style refinement helps
mainly in low-margin ambiguous cases, but neither effect overturns the broader ranking against
random placement and strong flat baselines. A final matched-budget scale sweep makes the
caution sharper: the current implementation does not yet validate the architecture at scale.

1 Problem and Claim
This paper studies a simple question: can a hair-like memory system use structured placement to
retrieve the right item more effectively than a flat content-addressed baseline? In the model, each
follicle stores aroot summary, which acts like a compressed retrieval key, and ashaft content, which
stores the detailed memory. A global controller—the “scalp”—first searches the root summaries
and then reads out the selected shaft.
The central claim is now narrower and clearer than in earlier drafts. Structured placement does
sometimes help, but only once retrieval explicitly exposes local or multi-root structure. The larger
lesson is that candidate discovery has improved substantially, whereas the remaining end-to-end
failure is concentrated in the final judgment stage: the system often surfaces a good pool and then
fails to choose correctly inside it. The main text therefore emphasizes the current mechanism, the
clearest empirical takeaways, and the updated bottleneck diagnosis. Detailed run-by-run history is
retained in the appendix.

diagnostics, performance rises strongly with root dimension and falls sharply with query noise.
When leak is removed, spiral and random placement become essentially identical, which shows that
the dominant early failure is not geometry by itself but information loss in the compressed root.
The later oracle-control split makes this even clearer: passive top-1 remains near 0.25–0.26 item
accuracy in the main setting, the candidate oracle jumps to about 0.52, and the local oracle rises
further to about 0.55. Root compression and root ranking therefore account for the largest share
of lost accuracy, while neighborhood selection contains a smaller but still recoverable contribution.
2. Structured placement changes geometry reliably, but only weakly improves retrieval
unless the search rule uses that structure directly.The spiral layout consistently produces
cleaner spacing and lower interference than random placement. That structural advantage is real,
but most passive retrieval rules do not convert it into much end-to-end gain. The first clear signal
appears only once retrieval becomes locality-aware: the v3 two-stage reranker gives spiral a small
but repeatable edge over random, the v4 spatial-window variant removes that gap, and the v5
active-local follicle restores a modest spiral advantage under several settings. The right claim is
therefore limited but meaningful: spatial regularity helps only when retrieval explicitly exposes
local structure, and even then the effect remains modest.
3. Multi-root retrieval and overlap are the strongest practical advances so far.The
biggest change in belief across the project is that candidate discovery is no longer the main weakness
in the same way it was earlier. Query-based reranking already helps substantially, and the later
multi-root union experiments are the largest practical jump: at the main operating point, retrieval
rises to about 0.77 item accuracy, while the oracle union reaches about 0.90. Overlapping root
assignment and larger root shortlists improve coverage further, with overlapk= 3 and top-k= 10
clearly outperforming narrower settings on average. These results make the architecture look more
viable than the early single-root experiments suggested. The system can now expose a strong
candidate set; it just does not yet score that set well enough.
4. The dominant unresolved problem has shifted to within-pool judgment.Once the
candidate pool becomes strong, the practical system still usually trails a flat key nearest-neighbor
baseline. In the main scale comparison, flat search reaches about 0.80 item accuracy while multi-
root reranking remains near 0.77, even though the oracle union is far higher. Later judge-stage
experiments all reinforce the same point. Soft local smoothing is at best marginally helpful, naive
averaging is destructive, shallow learned judges do not close the gap, guarded variants improve
stability but not enough strength, adaptive shortlist sizing helps only slightly, and controller-style
overwrite or restart mechanisms do not materially change the ranking. The clearest updated
conclusion of the paper is therefore that exposing better candidates is no longer enough: the
system still lacks a stable, expressive scorer inside the discovered pool.

A Experimental Appendix
This appendix preserves the detailed experimental record behind the main claims. The main text
now foregrounds the stable conclusions: root compression remains the first bottleneck, multi-root
and overlap mechanisms materially improve candidate access, and the remaining end-to-end gap
is concentrated in within-pool judgment. The subsections below keep the narrower ablations,
intermediate failures, and run-by-run implementation history that support those conclusions.
Each subsection still answers four questions for a run:whatwas tested,howit was implemented,
whatthe result was, andwhat we learned. That format makes it possible to preserve the project’s
full trajectory without forcing the main narrative to read like a lab notebook.
A.1 Run A: Leak Sweep
What was tested.This run tests whether a more regular placement geometry helps protect
memory retrieval when writing one follicle leaks into nearby follicles.
How it was done.Root dimension was fixed at 16 and top-kretrieval was fixed at 1. Leak
strength was swept from 0 to 0.35, and results were averaged over five seeds. Spiral and random
placement were compared directly under the same leakage rule.
What happened.Figure 1 shows that both layouts degrade smoothly as leakage increases. At
zero leak, spiral and random are identical, both reaching answer accuracy 0.138. At leak 0.35,
random ends at 0.0945 while spiral ends at 0.0875.
What we learned.Spiral clearly improves geometry, but not yet final retrieval. The mean
nearest-neighbor distance is 0.1052 for spiral versus 0.0590 for random, and the interference score
is 0.0516 for spiral versus 0.0567 for random. So the geometry signal is real, but the current memory
and decoding scheme is too weak to turn that structural advantage into better performance.

A.2 Run B: Root-Dimension Sweep
What was tested.This run tests whether the main bottleneck is spatial placement or root
compression.
How it was done.Leak was set to zero so that placement effects were removed. Root dimension
was swept across 8, 16, 32, and 64, while all other settings were held fixed. Spiral and random
layouts were both evaluated, again averaged across five seeds.
What happened.Figure 2 shows that spiral and random overlap exactly at every root dimension.
Accuracy rises sharply with root size: 0.057 at 8, 0.138 at 16, 0.296 at 32, and 0.485 at 64.
What we learned.This is the cleanest result in the current study. Without interference, place-
ment does not matter at all in the present code; only the root representation matters. That
means the compressed root is the main failure point in the baseline system. A 16-dimensional root
compressing a 64-dimensional key is simply too lossy for stable retrieval.

How it was done.Leak was fixed at 0.10 and root dimension was fixed at 16. Retrieval was

A.5 Run E: Locality-Aware Two-Stage Retrieval (v3, merged rerun)
What was tested.This run asks whether spiral placement can matterdirectlyin retrieval rather
than only through leakage. The main idea is to create clustered memories, preserve their write-
order locality, and then use a two-stage retrieval rule that explicitly looks at geometric neighbors.
This subsection now combines the original v3 run with a later near-duplicate rerun whose plots are

cleaner but whose conclusions are essentially the same.
How it was done.Memories were organized into 64 semantic groups of size 4. Items in the same
group were created by adding jitter around shared key and value centers, so that nearby memories in
write order were semantically related. Retrieval used two stages: Stage A performed a global coarse
search over root summaries, and Stage B reranked the top global candidates using support from
their local geometric neighborhoods. Three sweeps were evaluated: local neighborhood size, root
dimension, and query noise. In the refreshed rerun, the plotting was cleaned up and the baseline
global top-1 curve was shown more explicitly, but the retrieval rule and qualitative outcome stayed
almost unchanged.
What happened.The key pattern is that spiral finally shows a small but consistent retrieval
advantage once locality is used explicitly. In the local-neighborhood sweep, spiral local rerank
accuracy is higher than random at neighborhood sizes 3, 5, 9, and 15, and essentially tied at 25.
At local neighborhood size 9, spiral reaches 0.2568 while random reaches 0.2471. The refreshed
rerun makes the same point a little more clearly by showing the stage-1 global top-1 baseline
directly: local reranking exposes a small spiral edge, but both reranked curves still sit below the
stronger global baseline. In the root-dimension sweep, spiral again slightly exceeds random at root
dimension 32 (0.2568 versus 0.2471) and 64 (0.4279 versus 0.4266). In the query-noise sweep, the
two placements remain very close, with the rerun again showing that both layouts degrade similarly
as noise rises.
What we learned.This is the first run where it is reasonable to say that structured placement
helps retrieval a little once retrieval is made locality-aware. The rerun strengthens confidence
in that claim because the same qualitative pattern survives minor implementation and plotting
changes. However, the effect is still weak. The most important limitation is that the second-stage
reranker often performs worse than the original stage-1 global top-1 result. For example, with
local neighborhood size 9, global top-1 accuracy is 0.2747, while the reranked accuracy falls to
0.2568 for spiral and 0.2471 for random. That means the local neighborhood vote is exposing a
real spiral signal, but it is also dragging performance down by averaging in unrelated neighbors. A
likely reason is that the semantic group size is only 4, while the reranker often consults 9 or more
geometric neighbors, so many irrelevant follicles are being allowed to influence the decision.
A careful summary of Run E is therefore: structured placement gives a small and consistent retrieval
benefit once locality is used in the search rule, and a near-duplicate rerun confirms that this
conclusion is not a plotting accident. At the same time, the current local jury is still too noisy.
This points directly to the next experiment: tighten the spatial window or replace soft local voting
with winner-takes-all routing.

A.6 Run F: Spatial-Window Retrieval (v4)
What was tested.This run asks whether a stricter spatial-window rule can make spiral placement
matter more directly. Instead of using a soft local jury around several candidates, the system first
selects a strong global candidate and then opens only a local spatial window around that candidate.
How it was done.Memories remained clustered as in Run E. Retrieval worked in two stages:
Stage A performed global coarse search over root summaries, and Stage B restricted attention to a
fixed spatial radius around the selected candidate. Three sweeps were evaluated: spatial window
radius, root dimension, and query noise. The intention was that spiral placement would benefit
from cleaner local structure, while random placement would suffer from noisier neighborhoods.
What happened.Figure 9 shows the main result immediately: spatial rerank accuracy is flat
across all tested window radii, and the spiral and random curves overlap almost perfectly at about
0.2747. The same pattern holds in the root-dimension and query-noise sweeps. At root dimensions
8, 16, 32, and 64, spiral and random are numerically identical in spatial rerank accuracy. Likewise,
across query noise values 0.1, 0.2, 0.3, and 0.4, the two placements again overlap exactly.
What we learned.This is an important negative result. The spatial-window version does not
extract a useful spiral advantage; in practice it collapses to the stage-1 global top-1 behavior. The
likely reason is that the windowed refinement is not adding real discriminative information beyond
the best coarse candidate, so geometry is again present structurally but inactive functionally. In
that sense, v4 strengthens the conclusion that passive geometric organization alone is not enough.
If the project continues, the next step should probably be a more active follicle mechanism or a
stronger learned routing rule rather than another passive locality heuristic.

A.7 Run G: Tiny Active Follicle Refinement (v5)
What was tested.This run asks whether adding a tiny active step inside a selected follicle
helps recover a spiral advantage more reliably than the fully passive versions. The comparison
includes three variants: passive top-1 retrieval, passive top-kpooling, and anactive localfollicle
that performs a small local refinement step after candidate selection.
How it was done.Memories remained clustered as in Runs E and F. For the active variant, each
selected follicle pooled local neighborhood information and then applied a tiny near-identity trans-
form followed by a Loose-Screw-style nonlinearity. The experiment compared the three variants
at root dimension 32 and query noise 0.25, and then swept root dimension, query noise, and local
radius for the active variant.
What happened.The main comparison shows a nuanced result. Passive top-1 remains the
strongest item-level baseline, reaching 0.2747 for both placements. Passive top-kis clearly worse at
0.2409 for both placements. The new active-local variant lands in between: random reaches 0.2685
item accuracy while spiral reaches 0.2745, almost matching passive top-1 for spiral but not quite
surpassing it. The same pattern appears in group accuracy, where spiral active-local reaches 0.3479
versus 0.3391 for random.
The sweeps show where the active step helps most. In the root-dimension sweep, spiral active-local
is slightly better than random at all tested root dimensions, with the gap growing by root dimension
64 (0.4479 versus 0.4305). In the query-noise sweep, spiral also stays slightly ahead across all noise
levels. The clearest separation appears in the local-radius sweep: as radius grows, spiral degrades
more slowly than random. At radius 0.20, spiral still reaches 0.2534 item accuracy while random
falls to 0.2122.
What we learned.This is the first run suggesting that a tiny active follicle may be more promising
than additional passive locality tricks. The gain is still modest, and the active variant does not
beat passive top-1 outright at the main operating point. However, unlike v4, it does recover a small
and consistent spiral advantage, especially when the local neighborhood becomes larger or the root
representation is stronger. A careful interpretation is that passive geometry alone is probably too
weak, but a small active process inside each follicle may help the system exploit spatial structure
more effectively.

A.8 Run H: QDMN-Style Active Follicle (v6)
What was tested.This run asks whether a tiny QDMN-style processor placed inside each follicle
can outperform the passive baselines. The idea is to go beyond passive lookup and let each selected
follicle run a small internal route of transformations before decoding the answer.
How it was done.The comparison included three variants: passive top-1, passive top-kpooling,
and aqdmn folliclevariant with a small internal routeF→U→B→D→H. The follicle
processor was trained on local context features built from the query root, candidate root, and
neighborhood context. Root-dimension, local-radius, and query-noise sweeps were also run for the
active follicle.

A.9 Run I: Cause-Pinpoint Diagnostic (Part 3)
What was tested.This run was designed as a diagnosis rather than a new architecture. The goal
was to separate three possible failure sources in the hair-memory setup: root compression loss, noisy
neighborhood aggregation, and spatial contamination from write leakage. Instead of introducing a
more complicated follicle processor, the run compares several deliberately simple retrieval rules to
see which failure source is currently dominant.
How it was done.Five retrieval modes were compared: passive top-1, passive top-kpooling,
clean-jury best-1, context-soup pooling, and selective routing. The clean-jury variant chooses a
single best local neighbor rather than pooling many neighbors. The context-soup variant deliber-
ately averages a local neighborhood, making it a direct test of whether local pooling introduces
noise. The selective-route variant gates between the global candidate and the best local neighbor.
Multi-seed sweeps were then run over root dimension, query noise, write leak, and local radius for
both spiral and random layouts. In addition to item and group accuracy, the run also recorded
root hit rates, local coverage of the true item, neighborhood size, gate values, and basic geometry
statistics.
What happened.The main comparison is striking because it is so stable. At the default setting,
passive top-1 reaches item accuracy 0.2773 for spiral and 0.2826 for random. Clean-jury best-1
and selective routing are effectively identical to those values, while context-soup pooling is worse
at 0.2663 for spiral and 0.2578 for random, and passive top-kpooling is worse still at 0.2461 for
spiral and 0.2428 for random. The root-dimension sweep shows the same ordering at every tested
dimension: performance rises from about 0.04 at dimension 8 to about 0.44 at dimension 64, and
the clean-jury and selective-route variants simply ride on top of passive top-1 rather than improving
it. The query-noise sweep shows another strong pattern: all methods are near-perfect at noise 0.10,
collapse to roughly 0.46 by noise 0.20, and fall below 0.10 by noise 0.40, again with only small
differences among the top-1-style rules.
The write-leak sweep is comparatively flat. Over leak values from 0.00 to 0.20, passive top-1 only
drifts from 0.2852 to 0.2760 for spiral and from 0.2852 to 0.2806 for random. That decline is real,
but it is much smaller than the swings caused by root dimension or query noise. The local-radius
diagnostic adds one more useful clue. Local coverage of the true item rises as radius expands,
reaching about 0.6120 for spiral and 0.6393 for random at radius 0.20, yet clean-jury accuracy
stays almost perfectly flat near 0.277 to 0.283. So giving the jury access to more of the right local
region does not translate into better retrieval under the current decoding rule.
What we learned.This run narrows the failure point substantially. The most damaging operation
is not moderate write leakage, and it is not the mere absence of local candidates. If either of those
were the primary problem, then clean-jury or selective routing should have produced clear gains
once local coverage increased. Instead, the near-perfect tie between passive top-1, clean-jury, and
selective-route suggests that the global top-1 candidate is already doing almost all the useful work.
Meanwhile, both context-soup pooling and passive top-kpooling consistently hurt accuracy, which
means that averaging several shafts or several neighbors is currently more harmful than helpful.
The cleanest interpretation is therefore that root compression and pooled decoding remain the main
bottlenecks, while neighborhood aggregation mainly adds noise unless a much sharper routing rule
is introduced. In short: the jury is not blind, but it is not yet adding useful evidence.

A.10 Run J: Control-Oracles for Root vs Neighbor Failure (Part 4)
What was tested.This run extends the previous cause-pinpoint study by introducing explicit
oracle controls. The goal is to separate two questions that the earlier diagnostic could only hint at:
how much performance is lost because the root stage chooses the wrong candidate, and how much
is lost because the local routing stage fails to exploit the candidates that are already available.
The oracle methods are not deployable models; they are upper bounds used to show where the
recoverable headroom is located.
How it was done.The run compares six modes: passive top-1, passive top-kpooling, local-jury
best-1, selective routing, acandidate oracle, and alocal oracle. The candidate oracle assumes that,
among the global top-kcandidates, the system can pick whichever one is best for the true target.
The local oracle goes one step further and assumes that, across the union of local neighborhoods
around the top-kcandidates, the system can identify the best local item for the target. Multi-seed
sweeps were then run over root dimension, query noise, local radius, and write leak for both spiral
and random placement, while keeping the same clustered-memory setup as the previous diagnostic.

setting, passive top-1 reaches 0.2625 item accuracy for spiral and 0.2451 for random. The candidate
oracle then jumps to 0.5240 for spiral and 0.5174 for random, while the local oracle rises further
to 0.5445 and 0.5495. That means the largest recoverable gap is already present at the root stage,
but there is also a second smaller gap available at the neighborhood stage once the right local item
is identified. Selective routing, however, remains almost identical to passive top-1, and local-jury
best-1 is slightly worse for random and essentially tied for spiral. So the practical local methods
are recovering almost none of the signal that the oracle controls reveal.
This also clarifies what is failing inside the neighborhood. The local set is often informative: by
construction the local oracle can exploit it, and local coverage remains substantial. But the practical
aggregation rules behave destructively. In effect, the neighborhood contains a mixture of one useful
signal and many distractors, and naive pooling or weak jury rules wash the signal out instead of
isolating it. So the problem is not that neighbors are useless; it is that the current aggregation and

from roughly 0.05 at dimension 8 to about 0.42 at dimension 64, but the two oracle curves stay far

even when the root representation improves there is still large unrealized value in choosing better

A.11 Run K: Neighbor Aggregation Comparison (Part 5)
What was tested.This run asks a narrower question than the earlier oracle study: given the same
memory field, which simple local aggregation rule works best once a top root candidate has already
been selected? The goal is not to propose a new architecture, but to determine whether local aver-
aging, local top-1 picking, or temperature-controlled local softmax pooling can turn neighborhood
information into a real retrieval gain.
How it was done.The comparison included five modes: passive top-1, passive top-kpooling,
local average pooling, local top-1 pick, and local softmax pooling. The local methods all used the
best global candidate as an anchor, then inspected the spatial neighborhood around that anchor
within a chosen radius. The average rule pooled the local shafts uniformly, the top-1 rule chose the
highest-scoring local item, and the softmax rule used temperature-controlled weighting over local
root scores. Multi-seed sweeps were then run over root dimension, query noise, local radius, write
leak, and softmax temperature for both spiral and random placement.
What happened.The answer is cleaner than expected. At the main operating point, passive
top-1 reaches 0.2674 item accuracy for spiral and 0.2478 for random. Local top-1 pick is effectively
identical to those values. Local softmax pooling is the strongest local variant, but only by a hair:
it reaches 0.2487 for random and remains essentially tied with passive top-1 for spiral. In contrast,
local average pooling collapses badly, falling to 0.0929 for spiral and 0.0768 for random. Passive
top-kpooling is also clearly worse than passive top-1.
The sweeps reinforce that pattern rather than weakening it. Across root dimension and query noise,
local top-1 and local softmax pooling continue to track passive top-1 almost exactly, while local
average pooling remains far worse. The local-radius sweep is especially informative. For random
placement, local average pooling gets steadily worse as radius grows, and for spiral it stays harmless
only at very tiny radii where the neighborhood is effectively just the anchor itself. Once the radius
widens enough to include a real neighborhood, average pooling degrades sharply. The softmax-
temperature sweep shows the same story in another form: performance is best at low temperatures
and worsens as the softmax becomes flatter. The best temperature is 0.15 for random placement
and 0.05 for spiral placement, but even those best settings improve only marginally over passive
top-1. That means the winning version of local pooling is the one that behaves most like a nearly
hard selection rule rather than a true average.
What we learned.This run narrows the next step substantially. We still do not have a strong
neighborhood solution. The best local method is not a rich neighborhood combiner; it is a very

of extra information under the current setup. The practical implication is important: the prob-

top-1 neighbor selection is mostly neutral. The most honest conclusion is therefore that present
neighborhood methods are neutral or harmful except for very light smoothing.
That is still a useful negative result. It suggests that the next experiment should not ask how to
blend more neighbors, but how to introduce a sharper decision rule that only overrides the anchor
when a local alternative is clearly superior. In other words, the next gain is more likely to come
from hard selection or confidence-based routing than from broader local averaging.

B Appendix Summary
Across the current long experiment series, the pattern is now much sharper. Geometry matters
structurally, but root compression and final scoring remain the stronger immediate bottlenecks. The
passive variants rarely turn spiral geometry into a strong retrieval gain. Run I shows that pooled
decoding wastes much of the available local signal. Run J then separates the two main errors
cleanly: root ranking is the larger bottleneck, while neighbor selection still contains a smaller but
real recoverable contribution. Run K adds an important constraint by showing that the simple local
aggregation rules tested so far recover little of that signal. Local average pooling is destructive, local
top-1 pick is mostly neutral, and low-temperature softmax pooling is only a marginal refinement
over passive top-1.
Runs L–N then narrow the remaining target. Run L shows that query-based reranking and espe-
cially multi-root union improve retrieval strongly, so a single weak root search was a major source
of failure. Run M adds the key reality check: even with that stronger candidate pool, the practical
system still does not beat a strong flat key nearest-neighbor baseline, although the oracle union
does. Run N sharpens the diagnosis once more. Holding the strong candidate pool fixed, neither
a slightly richer heuristic judge nor a simple learned linear judge closes the remaining gap to flat
search, even though the oracle remains far above both. The paper can therefore now make a cleaner
final claim: the remaining failure is concentrated in candidate judgment, but the missing ingredient
is not merelysomeextra score terms or a shallow learned combiner. Future progress will likely
require a more expressive and more stable within-union scorer if strong candidate coverage is to
become a practical win over direct flat key matching.
Run O refines that conclusion one step further. Guarded judging helps robustness: it consistently
improves over the unguarded learned judges and prevents some severe failures under particular
splits or scales. But it does not change the main ranking. The best guarded methods still sit
slightly below flat key nearest-neighbor, while the oracle union remains far above them. That
means the paper can now distinguish two remaining needs inside the final decision stage: a scorer
that isstableand a scorer that isstrong. The current guards help with the first need more than
the second. A materially better within-union judge is still required if the strong candidate pool is
to become a practical end-to-end advantage.
Run P adds one last refinement on the discovery side. Adaptive shortlist order is useful: it increases
candidate coverage, raises the oracle ceiling, and gives a small practical improvement over the
fixed multi-root reranker. But it does not alter the main hierarchy. Flat key nearest-neighbor
still remains the strongest practical baseline, while the oracle adaptive union remains far above all
practical methods. That means the paper can now make an even cleaner final statement: candidate
discovery can still be improved around the edges, but the dominant unresolved problem is no longer
how to expose signal. It is how to judge the exposed signal well enough to convert a strong candidate
pool into a real end-to-end advantage.
Run Q tests that statement directly by strengthening the judge while holding the adaptive pool
in place. The result is informative rather than revolutionary. Extra judge complexity alone does
not close the gap. The best practical methods are still the adaptive heuristic mix and the guarded
linear judge, both of which remain slightly below flat key nearest-neighbor, while the oracle adaptive
union remains far above them. Moderate guard margins help, but local-radius tuning matters only
modestly, and higher projection count helps candidate access more than it fixes judgment. The
paper can therefore now sharpen its final bottleneck claim once more: the unresolved problem is
specifically astable, expressive within-pool scorer. Neither broader candidate exposure nor shallow
