Abstract
We introduceQuad-Directional Modular Networks(QDMN), an architecture-first framework
that treats computation as an explicit multi-directional fabric rather than a single feed-forward
pipeline. QDMN exposes four semantic processing directions—Forward (F), Backward (B), Up

1 Introduction
Neural networks are commonly described in terms of a forward pass (computing predictions) and
a backward pass (computing gradients). However, these notions conflate two distinct ideas: (i) the
semantic directionof information processing (e.g., refining, abstracting, reconstructing) and (ii) the
mathematical directionused by training algorithms (e.g., reverse-mode automatic differentiation).
This paper explores a framework question: can we make multiplesemanticprocessing directions
first-class primitives, so that inference is an explicit, programmable composition of directional
transformations?
We proposeQDMN(Quad-Directional Modular Network), a routing framework that:
•assigns modules to four direction symbols:F(forward/progression),B(backward/refinement
or consistency),U(up/compression or abstraction), andD(down/expansion or reconstruc-
tion);
•stores a mutable representation in a centralCoreNode;
•executes explicitroutes—sequences of direction symbols—with dimension-aware module dis-
patch.
What is new here (in this draft).The individual ideas of “up/down” (encoder–decoder pro-
cessing) and iterative refinement exist in many architectures. The intended novelty of QDMN is the
interface: a general, compositionalfabricin which multiple directional modules can be registered
and recombined. In particular:
•Up/Down as reusable primitives:“U” and “D” are not tied to one fixed encoder–decoder
graph; they are modules that can appear multiple times and interleave with refinement steps.
•Route-as-program:inference is controlled by an explicit route (e.g., [F,U,D,B,H]), en-
abling route switching at test time.
•Dimension-typed registry:modules are keyed by input feature dimension, making com-
patibility checks and multi-scale routing explicit.
•T oward grid-like composition:the same abstractions can be extended from 1-D routes
to 2-D “processing fabrics” (a grid of reusable directional transitions), although this draft
focuses on sequential routes.

QDMN is intentionallytraining-agnostic: it specifies a compositional scaffold rather than a
particular loss, optimizer, or a learned router.
Route length as a controllable variable.Unlike fixed feed-forward pipelines, QDMN exposes
inference depth via route length. Applying additional refinement steps (e.g., appending extra B
modules) is a form of test-time compute scaling, but monotonic improvement with depth is not
guaranteed without route-aware training objectives or explicit stopping criteria.
2 Related Work (Positioning)
QDMN is most closely related in spirit to (i) encoder–decoder and multi-scale architectures (where
“up” and “down” correspond to compression/expansion), (ii) iterative refinement and feedback-
style networks, and (iii) modular composition and routing/conditional-computation frameworks.
This draft doesnotclaim to invent compression/expansion or feedback. Instead, QDMN aims
to provide a small, explicitprogramming modelfor composing these behaviors: a dimension-aware
registry plus a route execution semantics. Unlike conventional encoder–decoder systems where
the up/down path is baked into a single graph, QDMN treats U and D as reusable modules that
can be invoked, repeated, and interleaved with refinement steps; and unlike learned routers (e.g.,
mixture-of-experts variants), QDMN foregrounds explicit, human-specified routes as a controllable
diagnostic and compute knob.

Interpretation of directions.The direction symbols are semantic labels rather than mathe-
matical inverses:
•F (F orward):advance a representation (prediction, progression).
•B (Backward):refine, critique, or check consistency against constraints.
•U (Up):compress/abstract (reduce feature dimension or complexity).
•D (Down):expand/reconstruct (increase detail or feature dimension).
3.3 Design Notes
Dimensional contracts.QDMN uses the last dimension of tensors as the routing “type”. This
supports vector, sequence, and image data, provided modules preserve all non-feature dimensions
(or do so intentionally).
Adapters.To connect incompatible feature dimensions across routes or across multiple QDMNs,
adapters (e.g., linear projections) can be inserted.
T raining.QDMN does not prescribe training. Common options include (i) route-conditioned
supervised loss, (ii) reconstruction losses for [U,D], and (iii) consistency losses for [F,B].

5 Experiments
5.1 Goals
We study QDMN primarily as an architectural abstraction rather than as a single task-specific
model. Our experiments target three questions: (i) can QDMN express common computation
motifs (direct prediction, compress–reconstruct, iterative refinement), (ii) can QDMN match simple
baselines on toy tasks under comparable training recipes, and (iii) what happens when we execute
longerroutes than those used during training (route switching / depth scaling).
5.2 Tasks
We use three small synthetic tasks (chosen for fast iteration and clear diagnostics): (1) 8×8 image
classification, (2) 1-D noisy sine regression, and (3) sequence parity (length 10). Full data generation
and model definitions are provided in Appendix A.

6.2 Depth generalization: naive vs stable refiners
A central motivation for QDMN is that inference depth is programmable via route length. However,
extending a route beyond its training depth is not guaranteed to improve performance. We therefore
evaluatedepth generalizationon a toy sine regression task by comparing: (i) anaiveQDMN trained
only at depth 1, and (ii) astableQDMN trained with a multi-depth objective.
Concretely, the model computes ˆy= D(Bd(ReLU(F(x)))) wheredis the inference depth (num-
ber of applications of B). We use a gated residual refiner with spectral normalization as a practical
stability mechanism.
Interpretation.The results support a conservative claim:depth generalization is conditional,
not automatic. When a refinement operator B is trained only for a single application, repeated
application can move the representation outside the manifold expected by the decoder. Multi-
depth training and gated residual refiners mitigate this by explicitly optimizing behavior across
multiple unroll depths.

7 Limitations
•QDMN is a compositional framework; performance depends on module choices and training
objectives.
•Explicit routing requires external logic (heuristics or a controller) and may be brittle without
careful design.
•Reusing the same refinement module multiple times at test time can be out-of-distribution
relative to training; without multi-depth training or a stopping rule, additional steps may
degrade performance.
•If modules change tensor shapes beyond the last dimension, additional bookkeeping is re-
quired.

8 Conclusion
QDMN reframes neural computation as an explicit multi-directional program over a shared core
state. By making routing and directionality first-class, QDMN provides a compact scaffold for
experimentation with refinement, abstraction, reconstruction, and adaptive inference.

class CoreNode(nn.Module):
def __init__(self, initial_dim: int):
super().__init__()
self._state: Optional[torch.Tensor] = None
self._dim = initial_dim
def set(self, x: torch.Tensor):
if x.shape[-1] != self._dim and self._state is None:
# allow initial state to set dim if created differently, but prefer consistent
initial_dim
self._dim = x.shape[-1]
self._state = x
self._dim = x.shape[-1]
def get(self) -> torch.Tensor:
if self._state is None:
raise RuntimeError("CoreNode␣empty:␣call␣set(x)␣first")
return self._state
@property
def dim(self) -> int:
return self._dim
class ModuleSpec:
def __init__(self, name: str, module: nn.Module, in_dim: int, out_dim: int):
self.name = name
self.module = module
self.in_dim = in_dim
self.out_dim = out_dim
class QDMN(nn.Module):
def __init__(self, initial_dim: int):
super().__init__()
self.core = CoreNode(initial_dim)
self.initial_dim = initial_dim
# registry: in_dim -> {symbol -> ModuleSpec}
self._registry: Dict[int, Dict[str, ModuleSpec]] = {}
def register_module(self, name: str, module: nn.Module, in_dim: int, out_dim: int,
replace: bool=False):
if in_dim not in self._registry:
self._registry[in_dim] = {}
if name in self._registry[in_dim] and not replace:
raise KeyError(f"Module␣for␣({name},␣in_dim={in_dim})␣already␣registered")
self._registry[in_dim][name] = ModuleSpec(name, module, in_dim, out_dim)
# register submodule for PyTorch tracking
self.add_module(f"mod_{name}_{in_dim}", module)

def _find_module_for_step(self, step: str, cur_dim: int) -> ModuleSpec:
if cur_dim not in self._registry:
raise RuntimeError(f"No␣modules␣registered␣for␣current␣dim␣{cur_dim}")
if step not in self._registry[cur_dim]:
raise RuntimeError(f"Module␣’{step}’␣not␣registered␣for␣dim␣{cur_dim}")
return self._registry[cur_dim][step]
def route(self, path: List[str], x: torch.Tensor, verbose: bool=False) -> torch.
Tensor:
# x shape (..., feature_dim)
if self.core._state is None: # allow core to accept this first input
self.core.set(x)
else:
# require input last-dim to match initial dim for reproducibility
if x.shape[-1] != self.initial_dim:
# allow but warn
pass
self.core.set(x)
if verbose:
print(f"QDMN.route␣start␣dim={self.core.dim},␣path={’->’.join(path)}")
for i, step in enumerate(path):
cur_dim = self.core.dim
spec = self._find_module_for_step(step, cur_dim)
out = spec.module(self.core.get())
if out.shape[-1] != spec.out_dim:
raise RuntimeError(f"Module␣’{step}’␣returned␣dim␣{out.shape[-1]}␣but␣
expected␣{spec.out_dim}")
self.core.set(out)
if verbose:
print(f"␣step␣{i+1}/{len(path)}:␣{step}␣({spec.in_dim}->{spec.out_dim})")
if verbose:
print("QDMN.route␣finished,␣final␣dim=", self.core.dim)
return self.core.get()

def mean_ci(a: List[float], alpha=0.05):
arr = np.array(a)
m = float(arr.mean())
if len(arr) <= 1:
return m, (0.0, 0.0)
s = float(arr.std(ddof=1))
n = len(arr)
se = s / math.sqrt(n)
z = float(stats.t.ppf(1 - alpha / 2, df=n - 1)) if SCIPY_OK else 1.96
return m, (m - z * se, m + z * se)

class BaselineMLP(nn.Module):
def __init__(self, in_dim=1, hidden=64):
super().__init__()
self.net = nn.Sequential(nn.Linear(in_dim, hidden), nn.ReLU(), nn.Linear(hidden,
1))
def forward(self, x):
return self.net(x.float())
class ContractiveRefiner(nn.Module):
def __init__(self, dim):
super().__init__()
self.linear = nn.utils.spectral_norm(nn.Linear(dim, dim))
self.gate = nn.Linear(dim, 1)
self.alpha = 0.08
def forward(self, x):
g = torch.sigmoid(self.gate(x))
delta = torch.tanh(self.linear(x))
return x + self.alpha * g * delta
class PlainRefiner(nn.Module):
def __init__(self, dim):
super().__init__()
self.net = nn.Sequential(nn.Linear(dim, dim), nn.Tanh())
self.alpha = 0.1
def forward(self, x):
return x + self.alpha * self.net(x)
class QDMNModel(nn.Module):
def __init__(self, refiner: nn.Module, hidden=32):
super().__init__()
self.F = nn.Linear(1, hidden)
self.B = refiner
self.D = nn.Linear(hidden, 1)
def forward(self, x, depth=1):
s = torch.relu(self.F(x.float()))
for _ in range(depth):
s = self.B(s)
return self.D(s)
